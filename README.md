## Start the project

1. Install Python 3.10+ and Node.js. Install dependencies:
   - `python -m pip install -r requirements-station.txt`
   - `npm.cmd install --prefix node-red` (use `npm` on Linux/macOS).
2. Run `./start.ps1` in PowerShell. Keep it open. It starts a local demo MQTT broker if port 1883 is free, then the SQLite/decision service, Node-RED and the sensor simulator. Do not run duplicate launchers.
3. Open `http://127.0.0.1:1880/dashboard/station` for results; `http://127.0.0.1:1880` is the flow editor.
4. The top panel receives live sensor data directly. The lower panel shows DB-backed ML comparisons, decisions and control performance.

On Linux/macOS start Mosquitto or `node node-red/demo-broker.cjs`, then `bash start.sh`.

## Train or refresh all five models

Keep the application running, then use a second terminal:

```powershell
python simulator.py --history
Invoke-RestMethod http://127.0.0.1:8765/health
# Wait until history_rows is 1008, then:
python ml_train.py
```

The simulator publishes a reproducible 42-day historical replay over `ev/telemetry`. Node-RED stores it in SQLite. Training reads only those stored rows. **Restart the service/launcher after training:** it loads and warms `artifacts/bundle.pkl` once at startup. Each paradigm has a regressor and an independent classifier; the validation-selected regressor supplies the forecast. Without artifacts, the dashboard shows `untrained_safe_rules` until restart with trained artifacts.

Models: decision tree, random forest, ANN with 64/32/16 hidden units, scaled SVR/SVC, and XGBoost. Metrics and artifacts appear under `artifacts/`. Load only artifacts generated by trusted local code.

## Responsibilities

| File | Role |
|---|---|
| `simulator.py` | Physical sensor/plant layer, MQTT telemetry and historical replay |
| `actuator.py` | MQTT command handler attached to the same plant; acknowledgement/timing |
| `station_core.py` | Vehicle physics, arrival/queue/departure and basic scheduler |
| `station_store.py` | SQLite ingestion and committed record reads |
| `ml_train.py` | DB-only training, five-model comparison, artifacts |
| `decision_engine.py` | Performance-gated forecasts, deadline rules, dwell and deadband |
| `tou_scheduler.py` / `tariff.py` | Deadline-constrained tariff optimization and simulated prices |
| `station_service.py` | Node-RED HTTP adapter and closed-loop metrics |
| `node-red/flows.json` | Independent live/storage paths and MQTT feedback |
| `evaluate_control.py` | Full-scenario comparison of all model policies and baseline |

The actuator shares station state with the simulator in one process, like a sensor and relay on one IoT node. Do not launch `actuator.py` separately. Old v3/v4 files are retained for reference; the launchers use the files above. Do not run the old Streamlit app because it starts legacy services.

## Verify and demonstrate

- Unit/behavioral tests: `python -m unittest discover -s tests -v`.
- Complete integration test: stop the application to free ports 1880/1883/8765, then `python tests/live_check.py`. It starts its own stack, replays history, trains, checks MQTT actuation and persistence, and stops its processes.
- Offline control comparison: `python evaluate_control.py`.
- Observe arrivals/queues and the two dashboard panels. Inspect `ev/ack` in the Node-RED debug sidebar.
- Stop the analytics service: the direct live panel continues; commands expire and charging stops. Restart the service to recover.
- Edit capacity or synthetic vehicle parameters in `station_core.py`, restart, and explain changed decisions. Some requests deliberately cannot be met.

All forecasting data are synthetic. Metrics are demonstrations, not real-world validation. The original overloaded scenario misses targets; the report includes this result. Faculty dataset/simulator approval is still unverified.
